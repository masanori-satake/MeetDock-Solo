## 2026/09/14 - 外部 ICS データからの制御文字・巨大入力による UI 障害および DoS の防止
**脆弱性:** 外部から取り込まれる `.ics` カレンダーファイルのパース処理において、入力サイズ無制限および抽出フィールド（SUMMARY, ORGANIZER 等）のサニタイズ不足による、制御文字（`\x00-\x1F\x7F`）混入に伴う UI 表示崩れ・ログ注入や、巨大ファイルによる CPU/メモリ枯渇 (DoS) のリスク。
**学び:** ドラッグ＆ドロップやファイル選択などユーザー起点で取り込まれるカレンダーデータは未検証の外部入力であり、パースエンジン層で厳格な文字サニタイズとファイルサイズ制限（`MAX_ICS_CONTENT_SIZE`）を行わなければ、拡張機能プロセスの応答停止や表示障害を引き起こす。
**予防策:** 外部ファイルやテキストパースを行うすべてのエントリーポイントで、サイズ上限チェックと制御文字の除去・長文字制限（`cleanIcsField`）を多層防御として徹底する。

## 2026/09/13 - 外部ネットワークレスポンスの無制限蓄積によるメモリ枯渇 (DoS) の防止
**脆弱性:** `https.get` 等による外部 API リクエスト処理時において、`res.on('data')` でレスポンスデータの累積バイト数を検証せずに結合を続けることによる、メモリ枯渇（Out of Memory）および拡張機能プロセスの DoS リスク。
**学び:** 信頼できる API（例: GitHub API）であっても、通信経路上のプロキシや予期せぬ巨大レスポンスを受信した場合に、サイズチェックのないデータ受信処理があるとメモリを急速に消費してアプリがクラッシュする危険性がある。
**予防策:** 外部 HTTP リクエストのデータ受信時には必ず最大受信サイズ制限（`MAX_RESPONSE_SIZE`）を設け、上限を超過した場合は即座に `req.destroy()` で接続を破棄・中断する多層防御パターンを適用する。

## 2026/09/12 - Teams URLの検証と安全な openExternal 呼び出し
**脆弱性:** `vscode.env.openExternal` への未サニタイズな URL の受け渡しによる任意コマンド実行 / 不安全スキーム（`command:`, `javascript:`, `file:` 等）および非許可ドメインのオープンリスク。
**学び:** パース時やユーザー入力時に URL バリデーションを行っていても、`globalState` や外部入力から不安全な URI が渡された場合に防御層が欠如していると `openExternal` 経由で危険なアクションが実行される危険性がある。
**予防策:** 外部 URI を開く処理は必ず中央集約型のセキュリティ検証ヘルパー（`isValidTeamsUrl` / `openTeamsMeetingUrl`）を介して厳格にスキーム（`https`）とドメインをチェックしてから実行する（多層防御）。
